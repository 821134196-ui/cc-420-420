# 楼宇门禁卡发放与离场回收系统

管理楼栋、租户、人员、门禁卡、权限组、有效期限、临时卡、挂失与回收记录。
仅依赖 Python 3 标准库（SQLite + http.server），无需安装任何第三方包。

## 单条命令本地启动

```bash
python3 app.py            # 首次启动自动建库并预置 发卡/挂失/回收 演示数据
# 或指定端口并重置数据： python3 app.py --port 8080 --reset
```

打开 http://localhost:8000 ，顶栏可切换岗位：

| 岗位 | 权限 |
|---|---|
| 管理员（admin） | 全部：发卡、改权限组、切设备、挂失、回收 |
| A/B 柜台（clerk_a / clerk_b） | 发卡、挂失、补卡、损坏、转交、回收、设备补传；**不能**改权限组、不能切设备离线 |
| 审计员（auditor） | 只读查询，所有写操作 403 |

## 核心业务规则

- **激活前置**：门禁卡必须同时绑定人员与权限组才能激活；发卡后自动写入设备并激活。
- **权限计算**：按 `楼层 × 时段 × 生效日期` 三维判定，任一不满足即拒绝并记录越界事件；
  挂失/损坏/回收/到期卡直接禁行。
- **离场回收**：先冻结权限，再登记回收记录（保存回收前卡片状态），人员无在持卡时自动标记离场。
- **挂失与补卡**：挂失即时冻结；**挂失卡不能补录原卡号恢复**，只能换发新卡，新卡 `replaced_by_id` 保留与旧卡的关联。
- **临时卡**：必须填到期时间，进程内定时任务（默认 10s 扫描）自动置为到期失效并留事件。
- **管理员改权限**：修改已有楼层规则必须二次确认（`confirm=true`），未确认的尝试也写审计事件。
- **卡号唯一**：发卡用 `BEGIN IMMEDIATE` 立即事务；两个柜台并发发放同一卡号时只有一笔成功，
  另一笔返回业务错误并记录"重复发放被拒"事件。
- **设备适配**：设备离线时发卡授权进入 pending 队列（卡片可激活但标记未下发），
  恢复后由管理员/柜台执行补传，批量写回并回填 `device_delivered`。
- **事件**：发卡、激活、挂失、非法补录拒绝、补卡换新、损坏、借用转交、
  权限越界/重复发放、设备离线、离线补传、回收、到期、改权限、改权限拦截全部留痕。

## 界面

- 配色：白色 + 深石板灰 + 电光蓝。
- **人员台账 / 门禁卡库存 / 权限组 / 发卡回收 / 挂失处理 / 审计查询** 六个页签。
- 楼层权限以 **权限组 × 楼层矩阵** 呈现：蓝=当前可通行、琥珀=有权限但非当前时段、
  灰=超出规则生效日期、斜纹=无权限。
- 门禁卡卡片左侧 **状态色带**：蓝=可用、红=挂失、琥珀=待回收/损坏、紫=临时卡到期、灰=已回收。
- 发卡柜台为 **两步**：① 填写发卡单 → 核对预填单（人员/门牌/楼层/到期/设备状态）→ ② 确认发放。
- 卡号、证件号、电话 **默认部分遮挡**（保留前 3 后 2）；仅管理员/审计员勾选"显示明文"可见全号，
  审计事件明细中的卡号同样随开关遮挡。

## 文件结构

```
app.py            HTTP 接口、两步发卡暂存、岗位鉴权、启动入口
core.py           SQLite schema、业务规则、权限判定、DeviceAdapter、到期定时线程
seed.py           演示数据（楼栋/租户/人员/权限组/发卡/挂失补卡/回收/离线补传/到期）
static/           index.html + app.js + style.css（无框架原生前端）
test_access.py    26 个测试（python3 -m unittest -v）
```

## 测试

```bash
python3 -m unittest -v
```

覆盖：楼层/时段/日期权限边界、未绑定不可激活、挂失卡不能补录恢复且补卡保留旧卡关系、
同卡号并发唯一、临时卡到期（手动 + 定时线程）、设备离线排队与恢复补传、
管理员/柜台/审计员岗位权限（领域层与 HTTP 403）、回收冻结与离场标记、二次确认、号码遮挡。
